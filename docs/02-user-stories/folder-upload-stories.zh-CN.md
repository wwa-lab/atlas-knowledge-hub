# 用户故事：文件夹上传（Folder Upload）

## 状态

草稿。Phase 1 前端，仅 mock。源自 `docs/01-requirements/folder-upload-requirements.md`。

## 角色

- **知识空间管理员** —— 上传文档包并创建批次。
- **交付负责人（Delivery Lead）** —— 跟踪批次进度并查看报告。
- **SME Reviewer** —— 待审核项的下游消费者（本切片仅做队列交接）。

## 故事

### US-FU-001 —— 启动文件夹上传（mock）

**作为** 知识空间管理员，**我想** 在 Documents 标签页点击 `Upload Folder`，**以便** 不离开演示就把项目文档文件夹带进空间。

覆盖：REQ-FU-001、REQ-FU-011、REQ-FU-013。

- **假如** 我在某知识空间的 Documents 标签页，**当** 我点击 `Upload Folder`，**那么** 打开 mock 上传流程并展示生成的文件清单，且**不**发起网络请求。
- **假如** 流程已打开，**当** 我查看，**那么** 它在视觉上与基线 Documents 标签页样式（面板、徽章、按钮）一致。

### US-FU-002 —— 启动 ZIP 上传（mock）

**作为** 知识空间管理员，**我想** 点击 `Upload ZIP`，**以便** 模拟摄取压缩文档包。

覆盖：REQ-FU-001、REQ-FU-002、REQ-FU-011。

- **假如** 我在 Documents 标签页，**当** 我点击 `Upload ZIP`，**那么** 打开同一 mock 清单流程，并标注为 ZIP 源包。

### US-FU-003 —— 审阅文件清单

**作为** 知识空间管理员，**我想** 看到每个检测到的文件及其路径、类型、大小，**以便** 在处理前确认包内容。

覆盖：REQ-FU-002、REQ-FU-010。

- **假如** 上传流程已打开，**当** 清单渲染，**那么** 每行展示原始相对路径、文件类型、mock 大小。
- **假如** 清单渲染，**当** 我查看每行，**那么** 它携带与 markdown 标准一致的 mock confidence 与 review-status 呈现。

### US-FU-004 —— 凸显不支持文件

**作为** 知识空间管理员，**我想** 明确标记不支持文件，**以便** 知道哪些文件不会被转换。

覆盖：REQ-FU-003、REQ-FU-009。

- **假如** 清单含有类型不被支持的文件，**当** 其渲染，**那么** 它被标记 `UNSUPPORTED` 并单独分组或加徽章。
- **假如** 所有文件都不支持，**当** 清单渲染，**那么** 空结果提示说明没有文件可处理。（REQ-FU-014）

### US-FU-005 —— 浏览文件树

**作为** 交付负责人，**我想** 把清单呈现为层级文件树，**以便** 理解包的目录结构。

覆盖：REQ-FU-004、REQ-FU-013。

- **假如** 清单含嵌套路径，**当** 文件树渲染，**那么** 文件夹与嵌套文件以可读层级出现，并带单文件状态徽章。

### US-FU-006 —— 由清单创建批次

**作为** 知识空间管理员，**我想** 确认清单并创建批次，**以便** 让文档包成为受跟踪的处理运行。

覆盖：REQ-FU-005、REQ-FU-006、REQ-FU-011。

- **假如** 清单非空，**当** 我确认，**那么** 创建新批次，含上传时间、owner、源包名、文件总数、单文件初始状态。
- **假如** 批次已创建，**当** 它出现，**那么** 每个文件项展示取自允许 File Status 集合的状态。

### US-FU-007 —— 跟踪批次进度与状态

**作为** 交付负责人，**我想** 看到批次摘要指标与处理进度，**以便** 评估文档包处理到何种程度。

覆盖：REQ-FU-006、REQ-FU-007、REQ-FU-008。

- **假如** 已创建批次，**当** 我查看，**那么** 我看到 总数 / PDF converted / Markdown generated / review required / failed / unsupported 指标。
- **假如** 已创建批次，**当** 我查看，**那么** 我看到 Office→PDF、PDF→Markdown、Source Trace 校验、SME Review 的进度列表与 mock 百分比。
- **假如** 批次处于 mock 推进，**当** 状态前进，**那么** 转换遵循 `docs/batch-processing-design.md` 的状态流。

### US-FU-008 —— 查看批次报告

**作为** 交付负责人，**我想** 看到 mock 处理报告，**以便** 在一处看到清单、不支持文件、失败、低置信、待审核项。

覆盖：REQ-FU-009、REQ-FU-010。

- **假如** 已创建批次，**当** 我打开其报告，**那么** 我看到清单、不支持、转换失败、低置信页、待审核项的计数与列表。
- **假如** 报告渲染，**当** 我查看任一项，**那么** source-trace、confidence、review-status 值都存在。

### US-FU-009 —— 保留可信元数据

**作为** SME Reviewer，**我想** 每个生成项都带 trace、confidence、review status，**以便** 待审核内容绝不被当作可信呈现。

覆盖：REQ-FU-010、REQ-FU-012。

- **假如** 任一生成的文件项或报告条目，**当** 我查看，**那么** 它携带 source-trace、confidence、review-status 字段。
- **假如** 低置信或生成项，**当** 其渲染，**那么** 默认 `REVIEW_REQUIRED` 而非已批准。

### US-FU-010 —— 双语与主题一致

**作为** 用户，**我想** 上传流程支持我的语言与主题，**以便** 与 Atlas 其余部分保持一致。

覆盖：REQ-FU-015、REQ-FU-013。

- **假如** 流程已打开，**当** 我切换语言，**那么** 所有新标签/消息更新，且我当前的清单/批次状态被保留。
- **假如** 流程已打开，**当** 我切换日/夜模式，**那么** 所有新界面经由共享 token 保持可读。

## 假设

- 批次创建与状态推进在内存中模拟；刷新后不持久。
- mock 清单从形似 `frontend/public/atlas-prototype.html` `batch.files` 的代表性样本种子化。

## 依赖

- 既有 `knowledge-space` Documents 标签页外壳与文案表。
- `docs/batch-processing-design.md` 状态模型；`docs/markdown-standard.md` 元数据字段。

## 范围外

- 真实上传、解析、适配器、持久化、API（见需求「范围外」）。

## 待解问题
