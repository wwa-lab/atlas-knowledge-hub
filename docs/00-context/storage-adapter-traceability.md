## Slice Contract

| Field | Value |
|---|---|
| Goal | Atlas can store and retrieve workspace-separated artifacts (raw, PDF, Markdown, assets, reports, Wiki) through a replaceable storage adapter without product-layer coupling to S3/MinIO. |
| Slice | `storage-adapter` |
| Phase | 3 adapter |
| Scope | Storage adapter contract, capabilities, store/get/list/delete/exists operations, workspace-separated layer policy, descriptors, storage operation records, metadata pointer write-back, mock-engine verification, API guide, tasks. |
| Exclusions | Real storage runtime, presigned URLs, retention/lifecycle policy, converter/parser execution, OCR/LLM, graph, Ask/RAG, publish-to-Wiki semantics, vector/model adapters, frontend UI, production auth/RBAC. |
| Verification row | Unit + integration tests against mock engines. |
| Constraints row | Parser/converter/model/vector/storage only through product-facing adapters; no direct tool calls; no hardcoded single implementation; secret masked; trace/confidence/review preserved. |

## Reconciliation Assumptions

- Layers committed as `raw`, `pdf`, `markdown`, `assets`, `reports`, `wiki`, aligned with `PROJECT_RULES.md` Workspace Separation and REQ-PROD-014.
- API returns descriptors only; object bytes stay behind the adapter (OQ-SA-002).
- First real storage engine choice (S3-compatible vs filesystem) is deferred (OQ-SA-001); the mock contract does not depend on it.
- The seam guard `S3` exception must be relaxed for the storage adapter package only; this is captured as T-SA-009 and DT-SA-001 so it is an intentional change.
