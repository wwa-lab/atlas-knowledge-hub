# Traceability: Vector Adapter

## Status

Implemented. The initial SDD was generated by the `atlas-sdd-generate-all` workflow for slice `vector-adapter`; the implementation pass completed the backend adapter/domain/API/test scope against `docs/03-spec/vector-adapter-spec.md` and `docs/06-tasks/vector-adapter-tasks.md`.

## Slice Contract

| Field | Value |
|---|---|
| Goal | Atlas can index approved or review-aware source chunks through a replaceable vector adapter and return traceable similarity evidence without product-layer coupling to pgvector, Milvus, Qdrant, or a single vector engine. |
| Slice | `vector-adapter` |
| Phase | 3 adapter |
| Scope | Vector adapter contract, capabilities, index/deindex/query operations, source-chunk trace preservation, vector run/result records, review-aware query policy, mock-engine verification, API guide, tasks. |
| Exclusions | Real vector DB execution, embedding/model provider calls, Ask/RAG answer generation, graph extraction, Wiki publication, frontend UI, production auth/RBAC. |
| Verification row | Unit + integration tests against mock engines. |
| Constraints row | Parser/converter/model/vector/storage only through product-facing adapters; no direct tool calls; no hardcoded single implementation; secret masked; trace/confidence/review preserved. |

## Reconciliation Assumptions

- Vector indexing starts from `source_chunk` evidence, not raw parser output.
- Query defaults to approved-only evidence; review-required chunks require explicit inclusion.
- Embeddings are supplied as mock/precomputed payloads in this slice; real embedding generation belongs to model-adapter or worker scope.
- First real vector engine choice is deferred; the mock adapter contract does not depend on it.
- The seam guard exception must be relaxed for the vector adapter package only; this is captured as T-VA-009.
